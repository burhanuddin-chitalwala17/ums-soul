# CHANGELOG — soul (project-wide context)

## Format
- **Append-only.** Never edit old entries. Corrections go in as new entries.
- Newest entries at the top.
- Entry header: `## [PR-XX] YYYY-MM-DD — Short title`
- Add `[API-BREAKING]` to the header if the cross-service contract (`CONTRACTS.md`) changed — this is the signal for all service repos that consume the contract.
- Soul tracks **cross-service** changes (workspace structure, contracts, project-wide ADRs, BACKLOG updates). Service-internal changes go in that service's own CHANGELOG.
- One entry per merged PR.

## [PR-04] 2026-07-07 — Specs centralized in `soul/docs/specs/`; ADR-04 amended
Refinement of PR-03. Specs now live in **`soul/docs/specs/`** (project-wide, one global SPEC sequence) rather than each service's `docs/specs/`. Rationale: a spec is forward-looking planning that pairs with `BACKLOG.md` and may span services (Phase 3 contract, Phase 5 feedback loop), so it doesn't belong inside a single service repo. The implementing service is now a field in the TRD, not the file's location. This sets the model: **soul = planning + cross-service context (backlog, specs, cross-service ADRs); services = implementation (code, tests, service-internal ADRs, service CHANGELOG)** — a deliberate asymmetry vs ADRs/CHANGELOGs, which still federate by scope. ADR-04 amended in place (same session, nothing built on the earlier wording). Moved the scaffold index from `../ums-watchkeeper-sentinel/docs/specs/` to `soul/docs/specs/` and repointed references in `soul/CLAUDE.md`, `BACKLOG.md`, and the `/ums-sdlc` + `/ums-brainstorm` skills (`spec-start` now scaffolds into `soul/docs/specs/`; TRD template field renamed owning→implementing service). No code, contract, or dependency changes.
